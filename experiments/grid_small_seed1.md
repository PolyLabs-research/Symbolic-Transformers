# Grid embedding ablation, reduced CPU run (seed 1)

Generated by `python scripts/grid_experiment.py --out-dir runs/grid_small --n-train 2000 --epochs 8`
plus `--arms learned_untied` for the control. Raw numbers: `grid_small_seed1.json` (one `evaluate_grid.py`
report per arm).

**Setup.** tiny model (2 layers, d=128), identical data and seed for every arm, 8 epochs,
batch 32, lr 0.0003. Indices for variables and predicates are drawn from
0-99 with 60-79 held out of training; `test_holdout` uses only the
held-out band, `test_far` only 100-199 (never in range). Train 32684 samples
from 2000 formulas. Arms: `learned`, `grid_linear`, `grid_conv` with tied output
weights, and `learned_untied`, the original model, as the control.

## Reading

1. **Syntax does not need the grids.** On seen indices every arm scores the same (53.6% overall, 74% on
   structure targets), and so does the untied learned control on the held-out band (53.6 / 74.6) and on the
   never-seen band (53.1 / 75.2). In this grammar every index is syntactically interchangeable, so any
   embedding that is not pathological carries the structure through. The thermometer panel is not needed
   for that.
2. **Tying the output to a learned table is what breaks on unseen indices.** The tied learned arm falls to
   25.8% on the held-out band and to 2.8% on structure targets after a numeral. Its unseen rows are never
   trained as inputs but are pushed away from every hidden state by the softmax denominator, so as inputs
   they are far out of distribution. The grid arms are immune because their rows are computed from the panel
   (grid_linear 53.6 / 75.2 on held-out). This is a real practical finding about weight tying with untrained
   tokens, not evidence that grids help syntax.
3. **Extrapolation beyond the trained range:** grid_linear keeps 68.7% structure / 62.8% after-numeral on
   100-199, grid_conv drops to 51.7 / 24.9 (it has never seen panels that full), untied learned is unaffected
   (73.8 / 75.2).
4. **Nobody copies.** `copy` accuracy (predicting a bound variable's index when it is reused) is at chance for
   every arm, 1.5-1.8% on seen indices against a pool of 80, and 0% on unseen indices. After 8 epochs on 2k
   formulas no model has learned variable binding, so the tied-output claim ("an unseen index can be
   predicted from its panel") is untested here, not refuted.
5. **The geometry is real but unused.** For grid_linear the nearest neighbour of a numeral embedding is an
   adjacent index 100% of the time (learned: 4-5%), Spearman(distance, |i-j|) 0.45 vs 0.01-0.11. Nothing in
   next-symbol prediction rewards that structure: FOL syntax never asks which index is larger.
6. **Panel noise is not free.** Flipping 1% of panel bits costs grid_linear 9 points overall and 5% costs 36.
   Training never saw noise.

## What this means for "making the grids matter"

The grids can only pay off on predictions where index identity or magnitude carries information. The
next-symbol task has almost none: the one index-sensitive prediction (copy) is 6% of positions and is not
being learned at this budget, and magnitude plays no role in the grammar. Two tasks would test the panels
directly:

- a binding task where the answer is an index (Phase 4 transitivity chains already have this shape:
  `VAR a EQUALS VAR b SEP ... QUERY VAR a ANSWER VAR z`), measuring copy accuracy on held-out indices with
  tied grid outputs against the learned table;
- a magnitude task (`NUM a LESS_THAN NUM b -> TRUE/FALSE`) on held-out pairs, where the thermometer code
  should generalise and a learned table cannot.

## Caveats

- Single seed, 8 epochs, 2k formulas, CPU. The full driver run (10k formulas, 30 epochs, 3 seeds) is the
  version to quote.
